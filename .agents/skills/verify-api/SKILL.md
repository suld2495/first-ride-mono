# API 요구사항 검증

curl 또는 스크립트로 API를 직접 호출해 요구사항이 실제로 충족되는지 확인한다.

**핵심 원칙:** 코드가 아닌 실제 응답을 검증한다. 성공 케이스뿐 아니라 에러 케이스도 반드시 확인한다.

## 언제 사용하는가

- API 엔드포인트 구현 후 요구사항 충족 여부 확인
- 응답 구조 및 상태 코드 검증
- 잘못된 입력, 미인증, 권한 없음 등 에러 응답 형식 확인
- 경계 조건(빈 값, 최대값, 중복 등) 처리 검증

## 요청 방법

**1. 서버 실행 확인:**

서버가 실행 중인지 먼저 확인한다.

**2. verify 서브에이전트 실행:**

Task 도구를 사용해 `api-verifier.md` 템플릿을 verify 서브에이전트에게 전달한다.

**플레이스홀더:**
- `{REQUIREMENTS}` — 검증할 요구사항 (기능 명세 또는 API 명세)
- `{BASE_URL}` — API 서버 주소 (예: http://localhost:8080)
- `{AUTH_TOKEN}` — 인증 토큰 (불필요하면 생략)
- `{DESCRIPTION}` — 무엇을 검증하는지 간단한 요약

**3. 결과 반영:**
- 실패 항목은 즉시 수정 후 재검증
- 통과 항목은 완료로 기록

## 예시

```
[회원가입 API 구현 완료]

[verify 서브에이전트 실행]
  REQUIREMENTS: POST /users — 이메일, 비밀번호를 받아 사용자를 생성한다.
                이미 존재하는 이메일이면 409를 반환한다.
                이메일 형식이 잘못됐으면 400을 반환한다.
  BASE_URL: http://localhost:8080
  DESCRIPTION: 회원가입 API 성공/에러 케이스 검증

[서브에이전트 결과]:
  통과: 올바른 입력으로 201 응답 및 사용자 ID 반환 확인
  통과: 중복 이메일로 409 응답 확인
  실패: 잘못된 이메일 형식에서 500 반환 — 400이어야 함
  판정: 일부 실패

[수정 후 재검증]
```
