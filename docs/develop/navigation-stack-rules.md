# 네비게이션 스택 규칙

## 목적

앱 내 화면 이동과 푸시 알림 딥링크에서 네비게이션 스택이 일관되게 쌓이도록 규칙을 정의한다.

## 페이지 동일성

현재 화면과 이동 대상의 **페이지 유형(라우트 패턴)**이 같으면 동일한 페이지로 본다.

동적 파라미터는 페이지 동일성 판단에 포함하지 않는다.

예를 들어 아래 두 경로는 같은 페이지 유형이다.

```text
/verification-requests/1
/verification-requests/2
```

## 이동 규칙

현재 최상단 화면과 이동 대상이 동일한 페이지 유형이면 `push`가 아니라 `replace`를 사용한다.

| 현재 화면 | 이동 대상 | 동작 |
| --- | --- | --- |
| 인증 요청 상세 A | 인증 요청 상세 B | `replace` |
| 사용자 상세 A | 사용자 상세 B | `replace` |
| 인증 요청 목록 | 인증 요청 상세 A | `push` |
| 루틴 화면 | 인증 요청 상세 A | `push` |

Expo Router에서는 다음 API를 기준으로 구현한다.

- 동일한 페이지 유형으로 이동: `router.replace(href)`
- 다른 페이지 유형으로 이동: `router.push(href)`
- 이전 화면으로 이동: `router.back()`

## 푸시 알림으로 인증 요청 상세에 진입하는 경우

현재 인증 요청 상세 A에 머무르는 중 새 인증 요청 B의 푸시 알림을 클릭하면 상세 A를 상세 B로 교체한다.

```text
변경 전: 인증 요청 목록 → 인증 요청 상세 A
변경 후: 인증 요청 목록 → 인증 요청 상세 B
```

상세 B에서 뒤로 가기를 누르면 이전 상세 A가 아니라 인증 요청 목록으로 이동해야 한다.

현재 화면이 인증 요청 상세가 아닌 경우에는 인증 요청 상세 B를 `push`한다.

```text
현재: 홈
이동: 인증 요청 상세 B
결과: 홈 → 인증 요청 상세 B
```

## 구현 시 확인 사항

- 동일 페이지 여부는 동적 `id`가 아니라 화면 또는 라우트 패턴으로 판단한다.
- 동일 페이지 유형으로 이동할 때 기존 상세 화면이 뒤로 가기 스택에 남지 않아야 한다.
- 푸시 알림 진입에서도 일반 화면 이동과 동일한 규칙을 적용한다.
- 화면을 교체한 뒤에는 새 동적 파라미터에 맞는 데이터를 다시 조회하거나 갱신한다.

현재 구현 위치:

- 페이지 유형과 이동 방식 판정: `apps/native/utils/navigation-stack.ts`
- 푸시 알림 이동 적용: `apps/native/app/_layout.tsx`
